# 单文件行数棘轮基线。
#
# 口径（2026-11-05 起）：**代码行** —— 不含注释、不含空行。
#   旧口径是「总物理行数」，注释与空行也占额度，导致 8 个已登记文件正好顶格
#   （InterviewAiService 403/403 等），连一行解释都加不进去 —— 门禁在惩罚注释。
#   这条门禁守的事实是「代码长到看不清」，不是「文字多」，判据必须与守护的事实同宽。
#   代价：历史发布说明与评审文档里的行数是旧口径，**不要与新数字直接比较**。
#
# 上限：src/main/java = 300 行；src/test/java = 400 行（2026-10-24 起，理由见契约类 javadoc）。
# 判据实现：src/test/java/com/intelligentresume/contract/SourceFileSizeRatchetContractTest.java
#
# 格式：<相对 server/ 的路径>=<允许的最大代码行数>，一行一条，路径用正斜杠。
#
# 四条规则（由门禁强制）：
#   1. **未登记**的文件，代码行超过**所在根的上限**（main 300 / test 400）→ 红（不许欠新债）。
#   2. 已登记文件**只允许下调**：实际代码行 > 登记值 → 红（旧债不许涨）。
#   3. 条目**失效** → 红：文件已不存在，或已降到上限内时必须删除该行（否则基线留空档，
#      「拆干净了又长回去」不会被发现）。
#   4. 基线必须可解析、无重复条目、路径为相对 server/ 的正斜杠路径、且必须落在某个扫描根下；
#      基线文件缺失 → 红。每个扫描根另有**扫描下限**（main 250 / test 120），任一根扫空即红。
#
# 登记 = 承认欠债并锁定上限，不是豁免。登记值取登记时的实测**代码行数**。
