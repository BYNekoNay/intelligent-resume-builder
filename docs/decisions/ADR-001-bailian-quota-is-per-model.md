# ADR-001: 百炼免费额度按模型维度独立计量

## Status: Accepted (2026-09-23)

## Background

2026-09-23 首次直连部署后，AI 全线不可用。当时的判断是「**账号级**免费额度耗尽」，
依据是配置的 `qwen3.7-plus-2026-05-26` 返回 `403 AllocationQuota.FreeTierOnly`。

**这个判断被实测推翻**：逐个真实调用后发现，额度是**按模型**独立计量的 ——

| 模型 | 实测 |
| --- | --- |
| `qwen3.7-plus-2026-05-26`（当时唯一配置） | 403 `AllocationQuota.FreeTierOnly` |
| `qwen-plus` | 403 `AllocationQuota.FreeTierOnly` |
| `qwen3.8-max` 等 8 个模型 | 200 正常 |

因此真正的病根不是"账号没额度了"，而是**单模型硬编码**：把可用性绑死在某一个模型的额度上。

## Decision

认定百炼免费额度**按模型**独立计量，并据此把"模型"从实现细节提升为一等配置维度：
AI 能力不得依赖任何单一模型，改为可配置的**有序模型链**（见 ADR-002）。

监控与告警同样按模型维度表达（`resume_ai_provider_calls_total{model=...}`、
`resume_ai_model_chain_available`）。

## Consequences

**正面**
- 单模型额度耗尽不再导致 AI 全线不可用，可由链上其他模型继续服务；实测已救回一次生成任务。
- 额度规划从"够不够用"变成"哪些模型还有余量"，可逐个补充。

**负面**
- 可用模型集合成为运行期状态，需要冷却/跳过逻辑，复杂度上升。
- 模型输出质量不再一致（换模型可能改变文风与 JSON 遵循度），需要更宽容的下游校验。
