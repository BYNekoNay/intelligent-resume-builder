# 接口设计说明书

## 1. 设计约定

### 1.1 接口风格

- 风格：RESTful
- 数据格式：JSON
- 鉴权方式：Bearer Token
- 字符编码：UTF-8

### 1.2 统一响应格式

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "traceId": "xxx"
}
```

约定：

- `code = 0` 表示成功
- 非 0 表示业务失败或系统失败

### 1.3 通用错误码建议

| 错误码 | 说明 |
| --- | --- |
| 40001 | 参数错误 |
| 40101 | 未登录或 Token 无效 |
| 40301 | 无权限访问 |
| 40401 | 资源不存在 |
| 50001 | 系统异常 |
| 50002 | AI 调用失败 |
| 50003 | PDF 导出失败 |
| 42901 | 请求频率或 AI 配额超限 |
| 40901 | 资源版本冲突或非法状态迁移 |

## 2. 认证接口

### 2.1 注册

`POST /api/auth/register`

请求体：

```json
{
  "username": "zhangsan",
  "email": "test@example.com",
  "password": "123456"
}
```

返回：

```json
{
  "userId": 1
}
```

### 2.2 登录

`POST /api/auth/login`

请求体：

```json
{
  "username": "zhangsan",
  "password": "123456"
}
```

返回：

```json
{
  "accessToken": "jwt-token",
  "accessTokenExpiresIn": 900,
  "refreshToken": "refresh-token",
  "userInfo": {
    "id": 1,
    "username": "zhangsan"
  }
}
```

### 2.3 刷新令牌

`POST /api/auth/refresh`

浏览器通过 `Secure`、`HttpOnly`、`SameSite=Lax` Cookie 提交刷新令牌。刷新成功后必须轮换 Cookie；已注销、过期、被撤销或已被替换的令牌不得再次使用。检测到旧令牌复用时撤销同一令牌族并返回 `40101`。

### 2.4 退出登录

`POST /api/auth/logout`

撤销当前刷新令牌和关联会话。访问令牌到期前无需写入完整 Token 原文到日志。

可选请求参数 `allSessions=true` 用于退出当前用户的所有会话；默认只退出当前会话。

### 2.5 获取当前用户

`GET /api/auth/me`

返回当前登录用户信息。

### 2.6 AI 数据处理同意

- `GET /api/ai/consent`：返回当前有效同意、提供商、用途、任务范围、数据类别和政策版本。
- `POST /api/ai/consent`：记录用户明确授权；必须提交 `policyVersion`、`providerCode`、`taskScopes` 和 `dataCategories`。
- `DELETE /api/ai/consent`：撤回同意，立即阻止新 AI 任务；不改写历史审计记录。

## 7. AI 接口

### 7.1 基于岗位生成简历

`POST /api/ai/generate-resume-for-job`

请求体：

```json
{
  "targetResumeId": 1,
  "jobDescriptionId": 2,
  "includedMaterialIds": [11],
  "excludedMaterialIds": [12],
  "preferredMaterialIds": [13]
}
```

返回示例：

```json
{
  "taskId": 1000,
  "status": "PENDING"
}
```

完成后通过 `GET /api/ai/tasks/{id}` 获取生成草稿、资料选择结果、来源映射和缺失项。用户确认采用时，服务端在同一事务中创建 `resume_version`、保存资料引用和确认时间。

生成任务的成功结果不得自动写入简历版本。客户端必须调用确认接口。

### 7.2 简历优化

`POST /api/ai/optimize`

请求体：

```json
{
  "resumeVersionId": 1,
  "jobDescriptionId": 2,
  "mode": "JD_OPTIMIZE"
}
```

返回 `202 Accepted`、`taskId` 和 `PENDING` 状态；优化内容只能在任务结果中返回，并由用户确认后保存为新版本。

### 7.3 重写自我介绍

`POST /api/ai/rewrite-summary`

### 7.4 重写项目描述

`POST /api/ai/rewrite-project`

### 7.5 查询 AI 任务状态

`GET /api/ai/tasks/{id}`

任务状态：`PENDING`、`RUNNING`、`SUCCESS`、`FAILED`、`CANCELLED`。成功结果必须包含输入快照摘要、模型/提示词版本、来源映射和用户确认状态。

### 7.6 确认或拒绝 AI 结果

`POST /api/ai/tasks/{id}/confirm`

请求头必须携带 `Idempotency-Key`，请求体必须包含客户端最后看到的 `taskUpdatedAt`。仅所属用户可确认 `SUCCESS + PENDING` 的任务。服务端在同一事务中校验来源、创建唯一 `resume_version`、写入资料引用并把任务标记为 `CONFIRMED`。

- 相同幂等键重放：返回已创建的版本，不能重复创建。
- 任务已被其他请求确认：返回现有版本。
- 任务结果已变化或状态不允许：返回 `40901`。
- 无法映射的 AI 自行生成事实不能通过确认接口直接采纳；用户必须主动编辑并通过职业资料接口新增事实。

`POST /api/ai/tasks/{id}/reject` 将确认状态改为 `REJECTED`，不创建版本。

### 7.7 实时优化与零碎资料导入

- `POST /api/ai/inline-optimize`
- `POST /api/ai/generate-resume-from-material`

两类接口均异步返回任务标识。零碎资料任务结果只能产生“待确认职业资料”和草稿简历，用户逐条确认后才写入职业资料库。

## 8. 成果量化与 ATS 接口

### 8.1 获取成果量化引导

`POST /api/ai/achievement-guidance`

请求体包含职业资料或简历片段；返回待补充的问题和已有内容风险。用户确认答案后，客户端通过既有资料或简历更新接口保存。

### 8.2 执行 ATS 体检

`POST /api/ats/check`

请求体：

```json
{
  "resumeVersionId": 1,
  "jobDescriptionId": 2
}
```

返回应包含总体分、通过项、风险项、优先修改项和解释。

## 9. 求职沟通与投递接口

### 9.1 生成求职沟通文案

`POST /api/communications/generate`

请求应包含简历版本、目标 JD 和文案类型（`COVER_LETTER`、`EMAIL`、`OPENING_MESSAGE`）；返回可编辑文案，不发送到外部平台。

### 9.2 投递记录 CRUD

- `POST /api/applications`
- `GET /api/applications`
- `GET /api/applications/{id}`
- `PUT /api/applications/{id}`
- `PATCH /api/applications/{id}/status`

状态更新请求必须包含 `targetStatus` 和当前 `version`。允许的基本迁移为 `DRAFT -> APPLIED -> INTERVIEWING -> OFFERED|REJECTED|CLOSED`；`CLOSED` 为终态，其他例外迁移由服务端拒绝并返回 `40901`。

### 9.3 面试答案资产

- `POST /api/interview-answer-assets`
- `GET /api/interview-answer-assets`
- `GET /api/interview-answer-assets?jobDescriptionId={id}&keyword={weakness}`
- `PUT /api/interview-answer-assets/{id}`
- `DELETE /api/interview-answer-assets/{id}`

### 9.4 AI 面试

- `POST /api/interviews/start`
- `POST /api/interviews/{id}/answer`
- `GET /api/interviews/{id}/report`

发起请求须指定 `sourceType`、面试模式和平台简历版本或外部简历文本；可选 `applicationRecordId` 仅用于关联一次投递。提交回答后返回本轮反馈和下一题；会话归属、轮次顺序和报告只允许所属用户访问。

## 12. 联调注意事项

- 所有需要登录的接口必须在 Header 中携带 `Authorization: Bearer {token}`
- 创建、更新类接口必须做参数校验
- `resumeJson`、`explanation` 等复杂结构字段建议前后端统一 Type 定义
- AI 接口需要约定好失败提示文案和重试逻辑
- 岗位定制生成接口必须返回资料选择结果；服务端需校验被引用资料和 JD 均属于当前用户
- 所有 AI 创建接口必须携带幂等键，并执行用户同意、输入长度、任务类型配额和限流校验
- 所有按 ID 查询的子资源必须沿父链校验当前用户归属，包括版本、AI 任务、评分、导出任务和文件；不得只按裸 ID 查询
- AI 任务轮询建议使用 1s、2s、4s、5s 的退避并以 5s 封顶；页面重载后必须能够从任务 ID 恢复，不得重复创建任务
- 投递状态更新必须带目标状态与乐观锁版本；非法迁移返回 `40901`
- 下载 PDF 时不得返回永久公开 URL；未登录、跨用户、过期和已删除资源均应拒绝
