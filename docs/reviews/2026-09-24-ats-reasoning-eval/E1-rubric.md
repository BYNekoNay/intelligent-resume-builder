# ATS AI 分析质量评分标准（Rubric v1.4）

> 用途：供**独立盲评者**对智历「ATS 智能检查」的两份匿名 AI 分析输出（一份开推理、一份关推理）打分，用于裁决「关闭推理后质量是否可接受」。
> 写法：契约式定义——锚定真实 DTO 字段、显式写清"不做什么"、把已知坑写成硬约束、以可机械执行流程收尾。

## 0. 元信息（先读，决定你怎么用这份文档）

- **被评对象**：智历「ATS 智能检查」的 AI 深度分析输出，结构即后端 DTO `AtsAiInsights`（字段见 §1）。本 Rubric 只评**内容质量**，**不评**延迟、token 成本、是否满足 JSON schema——这三项属确定性校验，不在本文档范围。
- **评分者**：独立盲评者，与实现者解耦；评分时只拿到两份匿名输出（记为 输出A / 输出B）+ 同一份简历原文 + 同一份 JD 原文，**不知道**哪份开了推理。
- **输入契约（评分者必须同时持有，缺一不得开评）**：① 简历原文全文；② JD 原文全文；③ 输出A 的 `AtsAiInsights`；④ 输出B 的 `AtsAiInsights`。缺 ① 或 ② 则无法判忠实度与引用精度。
- **评分对象模式（评分前必须由裁决者书面指定，二者不得混用）**：**模式 P（处理后输出，推荐）** = 经 `AtsAiResultValidator` 处理后的、用户实际看到的产物；**模式 R（原始输出）** = 未经校验器的模型原始响应。该选择决定 V2 是否生效（见 §6）。
- **本次目的**：判定「关闭推理」后的 ATS 分析质量是否仍可接受（判据见 §7）。
- **本次不做（out-of-scope）**：不评模型是否"更聪明"、不评文采、不评界面文案、不评响应时间与 token 成本；不改 DTO 结构；不实现任何实验。

## 1. 评分对象：DTO 字段 → 评什么的映射

| DTO 字段 | 含义 | 主要被哪个维度评 |
|---|---|---|
| `summary` | 1–500 字整体结论 | D5 |
| `semanticCoverage[]`：`requirement` / `status(MATCHED\|PARTIAL\|MISSING)` / `evidence(string\|null)` / `reason`，≤20 条 | 逐条覆盖 JD 要求 | D2（覆盖与判定）、D3（evidence）、D1（reason 中的事实） |
| `evidenceFindings[]`：`section` / `quote(string\|null)` / `assessment` / `suggestion` | 简历证据发现 | D1、D3、D4（suggestion） |
| `readabilityRisks[]` | 可读性风险 | D6 |
| `prioritizedActions[]`：`priority(P0\|P1\|P2)` / `section` / `action` / `basis` | 优先级行动项 | D4、D1（basis 中的事实） |
| `confidence` | 分析置信度 | D5 |

> **契约锚定**：本 Rubric 锚定上述字段名与枚举值（`MATCHED/PARTIAL/MISSING`、`P0/P1/P2`）。若实际 DTO 变更，本 Rubric 须同步修订后再用（活规格，见 §12）。

> **引用字段的观测前提（两个载体、处理方式不同，勿混同）**：
> - `evidenceFindings[].quote`：**被校验器处理**——`AtsAiResultValidator` 对不含于简历的 `quote` 静默置 `null`。故**模式 P 下 `quote` 层的假引文不可见**（→ §6 V2a）。
> - `semanticCoverage[].evidence`：**不被校验器处理**——假引文**在两种模式下都可见**（→ §6 V2b）。
> 结论：`quote` 与 `evidence` **口径不同、不得并论**；"假引文"在 `evidence` 层始终可观测，在 `quote` 层仅模式 R 可观测。

## 2. 六个可评分维度

**全局评分规则**：每维只取**整数 1–5 分**；锚点只给 1 / 3 / 5，若判 2 或 4，评分者必须写明"比低档多什么、比高档少什么"。同一维内若好坏并存，按"是否**成规模**出现"定档（单例→高档边界的减分理由；成片→低档）。

### D1 事实忠实度（权重 30）
**定义**：输出中一切**事实性断言**（`summary`、`reason`、`assessment`、`basis` 里对候选人经历/成果/技能的陈述）是否都能在简历原文或 JD 原文中找到直接依据。
**关键区分**：
- 允许：从原文**无损逻辑推出**且不放大程度的表述（原文"负责 A 模块开发"→"具备 A 模块开发经验"；原文列了两个项目→"有多项目经验"）。
- 不允许：引入原文没有的**新事实**或**抬高程度**（原文无"带团队"却称"有团队管理经验"；原文"参与"却称"主导"；编造数字、结果、证书、年限）。
- **1 分**：事实性断言**成片**无依据（≥3 条或占比明显），或出现 1 处**抬高程度**的实质误述。
- **3 分**：绝大多数断言有依据，仅 1–2 处**轻微**过度推断，且不改变结论方向。
- **5 分**：每条事实性断言均可定位到简历/JD 原文；推断均以"推断/可能"语境表达，不冒充事实。

### D2 JD 覆盖完整度与判定一致性（权重 25）
**定义**：`semanticCoverage[]` 对 JD 要求的覆盖是否完整，以及每条 `status` 与 `evidence` 是否自洽。
**关键区分**：JD 中带"必须 / 必备 / 熟练 / 精通 / ≥N 年 / 本科及以上"等**硬性要求**必须被覆盖；软性偏好可合并。
- **1 分**：遗漏 ≥1 条**硬性要求**；或存在 `status` 与证据**明显矛盾**（证据充分却标 MISSING；`evidence` 为 null 却标 MATCHED）。
- **3 分**：硬性要求全覆盖，软性要求遗漏 ≤1 条；个别边界条目的 PARTIAL/MATCHED 属可争议但方向正确。
- **5 分**：硬性 + 主要软性要求全覆盖；每条 MATCHED 都有简历原文支撑，每条 MISSING 都说明"简历缺什么"，PARTIAL 明说"满足到哪、缺哪"。

**覆盖判定不看"是否单列 MISSING"（与 K4 同口径）**：只要某硬性要求被**任一 `semanticCoverage` 条目**评估，并在其 `status`/`reason` 中明确了匹配程度与缺口（含整体判 PARTIAL、把确实缺失的项写进 `reason`），即视为**已覆盖**；**不得**因其"未单列成 MISSING 行"而判覆盖缺失（K4 同此口径，见 §5）。

**规则侧疑点例外（重要，防误扣 AI）**：若输出在某 JD 关键词上标 MISSING/PARTIAL，但该关键词**在简历原文中确实存在**（含组合词/同义表述，如 "Spring Boot"），**不得**据此扣 D2/K4/V——已知生产规则引擎存在同义词词典**系统性误报**（`app.scoring.synonym-dictionary` 运行时按空词典行为，多词关键词被 tokenizer 按空格切分而误判 MISSING；本轮不修以保基线）。此类条目记为**规则侧疑点**，在 §9 回传中**单列**、**不参与 AI 计分**，由 team-lead 转贝洛奇核实。**判据**：简历原文可逐字/同义命中该要求，而输出判缺 → 记规则侧疑点，AI 侧不扣分。

### D3 证据可核查性与引用精度（权重 15）
**定义**：`quote`、`evidence` 两个证据载体，是否给出**可回溯到原文**的引用，且该引用确实支撑其结论。
**引用三档（新增"半逐字"档）**：
- **逐字引用**：与简历原文逐字一致（归一化：忽略空白与中英文标点差异，其余必须一致）。
- **半逐字引用**：用**分隔符**节略或拼接多个真实片段；合格条件为**每个片段本身逐字可回溯** 且 **拼接后未改变原意**（不引入新事实、不夸大、不暗示原文没有的因果）。**半逐字不算编造。**
- **失真引用**：任一片段**无法逐字回溯**（出现原文没有的字），或拼接后**改变原意**（夸大/移花接木）。失真引用同时按载体触发 §6 V2a/V2b。

**分隔符与参照文本（裁定，防止规则被稀释）**：
- **分隔符集 = `…` `；` `;` `、` `,` `，` `。` `：` `:` `+`**（短语/句子级标点）——把各自逐字存在的片段用这些标点连接，**不构成编造**。
- **空白（空格、换行、制表）一律不作分隔符**（**关键边界**）：否则任何文本都能拆成孤词后"逐字命中"，引用检查形同虚设。操作上**先按分隔符切段，空白仅在段内做归一化、不触发分段**。
- **参照文本 = 简历的 full JSON（`serialize(resumeJson)`，含键名）**：与产品自身接地检查（`AtsAiResultValidator` 判 `quote` 所用参照）**对齐**，避免同一个"引用是否落地"的问题出现两套参照、导致文档自相矛盾。
- **重建式 JSON 片段**（如 `"skills":[{"name":"MySQL"}]`）→ 判为**转述**（其中 JSON 语法——花括号/键名/数组括号——是生成的文本、非被引原文，故**非"逐字引用"**；但未引入新事实，故**非幻觉、不触发 V2b**）→ 归入"相当比例为转述 → **D3=3**"，**不新增档位**。
**分档**：
- **1 分**：关键 finding 大量载体为空（`quote`/`evidence` 皆 null），或引用与结论**不对应**，或出现**失真引用**。
- **3 分**：多数载体非空且大致支撑结论；但相当比例为**转述**（非原文、无「…」标记）或**半逐字但有原意偏移**。
- **4 分**：介于 3 与 5——多数为逐字，少部分为**合格半逐字**（各片段可回溯且未改原意）。
- **5 分**：全部载体为**逐字引用**、可定位、且恰是支撑其结论的最相关片段。
**模式 P 下两载体的可观测性不同（修正）**：`evidence`（`semanticCoverage`）**不被校验器处理**，其非空比例与内容**在两种模式下均可直接判**；`quote`（`evidenceFindings`）在模式 P 下被静默置 null，其**非空比例是相对指标**（null 可能源于"无可引原文"或"编造后被抹掉"），**单臂绝对值无意义，只看两臂差异**，且只作佐证。

### D4 可操作性（权重 15）
**定义**：`prioritizedActions[].action` 与 `evidenceFindings[].suggestion` 是否具体到**可据以动手修改**；`priority` 与影响度是否一致；`basis` 是否给出理由。
- **1 分**：动作为放之四海而皆准的套话（"优化描述""突出亮点""加强量化"），无 `section` 指向或无法执行；或 `priority` 与影响度明显错配。
- **3 分**：部分动作具体（指明 `section` + 改什么），部分偏泛；`priority` 基本合理。
- **5 分**：每条 action 均指明具体 `section` + 具体怎么改（补充哪类信息/朝哪个方向改写），`basis` 关联到具体 JD 要求或风险，`priority` 与解决价值一致。
**套话判定（机械）**：把这条建议原文贴到任意**另一份**简历上仍成立、且句中不含**本简历/JD 特有信息** → 判为套话。

### D5 结论质量与置信度校准（权重 10）
**定义**：`summary` 是否给出可决策的整体结论且与明细一致；`confidence` 是否与**结论—证据的一致性**匹配（**不是**与覆盖率本身匹配）。
- **1 分**：`summary` 是套话/无信息量，或与 `semanticCoverage` 结论**矛盾**；或 `confidence` 与**结论—证据一致性**明显不符（结论含糊、大量边界 PARTIAL，却给高置信）。
- **3 分**：`summary` 准确但偏概括；`confidence` 大体贴合证据。
- **5 分**：`summary` 一句话给出"匹配到什么程度 + 核心理由 + 最主要缺口"，与明细一致；`confidence` 与**结论强度**对应。
**置信度校准口径（统一，修正原"覆盖低则置信低"的字面）**：置信度校准的锚点是**"结论方向是否明确、且证据是否一致"**，而非覆盖率高低本身。
- **高置信合理** iff 结论方向明确**且**证据一致——"匹配"有充分正证据，**或**"不匹配/错位"有充分反证据（含"JD 与简历几乎无交集"这一**强反证**）。
- **高置信失当** iff 证据不足或自相矛盾——结论模糊、或与语义覆盖证据冲突、或**覆盖率低却未给出"错位/严重不匹配"的明确结论**（含糊其辞却高置信）。
- 因此：**覆盖率低 + 明确判"错位" + 高置信 → 校准合理，不扣**；**覆盖率低 + 无明确结论 + 高置信 → 校准失当，扣**。

### D6 可读性风险识别的有效性（权重 5）
**定义**：`readabilityRisks[]` 指出的是否为简历中**真实存在**且**值得改**的可读性问题。
- **1 分**：风险项与简历实际无关（凭空捏造），或全为通用废话。
- **3 分**：多数风险真实、有一定价值，个别偏泛。
- **5 分**：每条风险都能指向简历中的具体位置/表述，且确实是会影响招聘方判断的问题。

## 3. 「看起来合理」与「真正可用」——本次评分的核心难点

盲评最易犯的错：只要输出**语句通顺、方向没错**就给高分。下列对照用于拉开学分：

| 维度 | 看起来合理（最多 3 分） | 真正可用（才配 5 分） |
|---|---|---|
| D1 | "候选人整体能力较强" | 每句判断都能指回简历哪一行 |
| D2 | 列了 8 条要求都给了 status | 硬性要求无遗漏，MATCHED 有原文、MISSING 说明缺什么 |
| D3 | 有 finding，也有 `quote` | `quote` 逐字可查且恰是支撑片段 |
| D4 | "建议优化项目经历" | "在【项目1】补 1 句容器编排的具体产出，以对上 JD 的 K8s 要求" |
| D5 | "匹配度较高" | "3 项硬性要求里 2 项 MATCHED、1 项 MISSING（K8s 实操），置信中" |
| D6 | "建议注意格式" | "第 2 段职责与业绩混写，招聘方难快速抓取成果" |

**一句话口诀**：能指着**具体字段里的具体一句**说明"它凭什么这么写"，才算真正可用；只能整体说"读着还行"，最多给到 3 分。

## 4. 权重与总分换算

| 维度 | 权重 | 满分贡献 |
|---|---|---|
| D1 事实忠实度 | 30 | 30 |
| D2 覆盖完整度与判定 | 25 | 25 |
| D3 证据可核查与引用精度 | 15 | 15 |
| D4 可操作性 | 15 | 15 |
| D5 结论与置信度校准 | 10 | 10 |
| D6 可读性风险有效性 | 5 | 5 |
| **合计** | **100** | **100** |

**换算公式**：加权分 = Σ(维度分 dᵢ × 权重 wᵢ ÷ 5)。
**总分** = 加权分 − Σ(§5 扣分)，下限 0；若触发 §6 任一一票否决，直接判 fail（总分置 0 并标记否决原因）。

## 5. 扣分项（可累加，逐项写明"因为 X 所以扣 Y"）

| 编号 | 扣分情形（定义） | 每次扣分 | 说明 |
|---|---|---|---|
| K1 | **空泛建议**：`action`/`suggestion` 命中 §D4 套话判定。**"ATS 通用建议"（如"按类别分组技能/补充熟练度"）同样命中**——只要满足套话判据（贴到任意另一份简历仍成立、不含本简历/JD 特有信息）即算，不因其属"ATS 常识"而豁免 | 每条 3 分，同一 `section` 多次只扣一次，本项最多扣 15；**若某输出的 action/suggestion 几乎全为通用建议（无一条含本简历/JD 特有信息），除 K1 计到上限外，D4 另判 ≤2** | 与 D4 维度分**可叠加** |
| K2 | **与简历无关**：finding/risk/action 指向简历中不存在或未涉及的 section/内容（分析对象错位，非 D1 式编造事实） | 每条 3 分 | |
| K3 | **与 JD 无关**：`requirement` 既不来自 JD、**也不服务于对该候选人相对本 JD 的贴合度判断**；或 action 与任何 JD 要求无关联 | 每条 3 分 | 两步判定：先查 JD 能否命中；不能命中再看是否为"贴合度观察"（见下） |
| K4 | **硬性要求遗漏**：JD 中标注"必须/必备/≥N 年/本科及以上"等的硬性要求，**未出现在任何 `semanticCoverage` 条目**（既无含它的条目，其 `reason` 也未提及）。**"未单列 MISSING"≠"未出现"**——折进 PARTIAL 并在 `reason` 说明缺口的，不算遗漏 | 每条 5 分 | 与 D2 可叠加 |
| K5 | **结论与明细矛盾**：`summary` 与 `semanticCoverage`/`evidenceFindings` 结论冲突 | 每次 8 分 | |

> **叠加规则**：维度分衡量整体水平；扣分项对**可机械计数的单点硬伤**做显式扣减。二者叠加是**有意设计**——一处硬伤既拉低整体维度分，又触发单点扣分，避免"整体还行"掩盖具体硬伤。

> **K3 两步判定（防误伤"贴合度观察"）**：对每个 `requirement`——(a) 是否能在 **JD 原文**命中？能 → **不判 K3**。(b) 不能命中 → 是否为**对该 JD/岗位的贴合度观察**（即它描述"这个岗位要什么 / 候选人相对该岗位如何"，如把 JD 隐含定位"后端开发工程师"显式化、把"稳定性治理"作为岗位相关能力列出）？**是 → 不判 K3**（记为 JD 隐含要求的合理显式化，不扣分）；**否**（引入与 JD 无关的外部要求，如无关行业/岗位的通用建议）→ **判 K3，扣 3 分**。

> **K4 判定（看"是否被评估 + 缺口是否说明"，不看行数）**：硬性要求只要被**任一 `semanticCoverage` 条目**评估、且缺口在 `status`/`reason` 中明确（如整体判 PARTIAL 并把确缺的 MySQL/Redis 写进 `reason`）→ **不判 K4**；只有**整条硬性要求在 `semanticCoverage` 中完全无迹**（无含它的条目、`reason` 也无提及）→ **判 K4，扣 5 分**。

## 6. 一票否决项（触发即判 fail，不再算分）

| 编号 | 否决情形（定义） | 判定证据 |
|---|---|---|
| V1 | **幻觉**：出现任何**编造简历中不存在的**经历、成果、技能、证书、年限的**事实性陈述**（含把"参与"抬为"主导"这类程度误述） | 逐条把断言对回简历/JD，找不到依据即命中 |
| V2a | **引用幻觉（`quote` 层，条件式）**：**仅模式 R 生效**——任一非空 `evidenceFindings[].quote` 按 §D3 分隔符集拆段、以 **resume full JSON** 为参照，任一片段**不存在**即命中；**模式 P 下 N/A**（已被校验器置 null） | 模式 R：拆段 + full JSON 参照，逐字检索失败即命中；模式 P：无观测对象 |
| V2b | **引用幻觉（`evidence` 层）**：**两种模式下均生效**——任一非空 `semanticCoverage[].evidence` 按 §D3 分隔符集拆段、以 **resume full JSON** 为参照，**任一片段不可回溯或拼后失真**即命中；**重建式 JSON 片段按「转述」处理，不触发本项** | 校验器**不处理** `evidence`，两种模式下均可见、均判 |
| V3 | **系统性无关**：输出整体与简历或 JD 之一无关（如通篇通用求职建议，不针对本简历/JD） | 抽查 ≥5 条断言，无一可绑定到简历或 JD |

> **为何 V1/V2 一票否决而非扣分**：本产品的核心承诺是"**有据可查**"。一处编造或一处假引用即可被用户当场证伪，产品信任当场崩塌——它无法用"别处做得好"补偿，故不可扣分了事。
> **与 D1/D3 的关系**：D1/D3 是**整体质量分档**，V1/V2 是**单点致命触发器**；同时存在时先判 fail。

> **V2 条件式说明（含 V2a/V2b，必读）**：
> 生产链路 `AtsAiResultValidator:44-47` **只对 `quote` 静默降级**——`if (!resumeText.contains(quote)) quote = null;`，响应仍通过；**它不处理 `semanticCoverage[].evidence`**。故两载体可观测性不同：
> - **模式 P（推荐，贴近用户体验）**：`quote` 层假引文不可见 → **V2a = N/A**；`evidence` 层假引文**仍可见** → **V2b 照常判**。`quote` 非空比例退化为**相对指标**（null 可能源于"无可引原文"或"编造后被抹掉"），只作佐证、只看两臂差异（见 §2 D3）。
> - **模式 R（原始输出）**：`quote` 与 `evidence` 均未被处理 → **V2a 与 V2b 同时生效**。
> **V1 在两种模式下均生效**：校验器不改写 `summary`/`assessment`/`reason`/`basis` 中的事实性陈述，幻觉（V1）始终可观测。
> **漏检说明**：把 V2 只锚在 `quote` 上会**漏检 `evidence` 层伪造**（本次 verifier-critic 发现的不自洽即此）——故本次拆为 V2a/V2b，覆盖 **`quote`（条件式）+ `evidence`（无条件）**。

## 7. 合格线：这是"可以关闭推理"的判据

### 7.1 绝对合格线（单份输出必须同时达到）
一份输出判 **PASS（内容合格）**，当且仅当**同时**满足：
1. 总分 ≥ **75**；
2. 无任一一票否决（V1/V2a/V2b/V3；**模式 P 下 V2a 记 N/A、V2b 仍判**，见 §6）；
3. D1 事实忠实度 ≥ **4**；
4. D2 覆盖完整度 ≥ **4**；
5. D3 证据可核查性 ≥ **3**。

**阈值理由**：D1+D2 合计权重 55，是产品价值的地基；要求二者均 ≥4 意味着"核心两维必须接近满分"。在此基础上总分 ≥75 相当于"其余四维平均约 3.4/5（中上）"——足以挡住"看着合理实则不可用"的输出（这类通常落在 60 上下），又不因措辞/长度等非核心退化而误杀。

### 7.2 灰色区
总分 **65–74**，或 D1/D2 落到 3，或 D3 = 2 → 判 **REVIEW（需人工复核）**，不得直接放行。

### 7.3 对比判据：关闭推理是否可接受（对 输出A、输出B 分别评完后）
设开启推理版为 R_on、关闭推理版为 R_off（评分者不知情，按 §10 揭盲后由裁决者套用）。**本节在 §7.5 实质性退化闸未拦截时适用**；本节所有"较 R_on 下降"**与 §7.5 同按臂均值口径**（`mean(off) − mean(on)`），**单样本**差值只记黄灯、不在此单独判定。

1. R_off 未达 §7.1 绝对合格线 → **不可关闭推理**。
2. R_off 达线，但在证据链三维 **D1 / D2 / D3** 中任一维**臂均值**较 R_on 下降 **≥ 2 分** → **不可关闭推理**（证据链退化不可接受；与 §7.5 单向阈值同向、同口径）。
3. R_off 达线，且 D1/D2/D3 各维较 R_on 下降 **≤ 1 分** → **可关闭推理**。
4. R_off 达线，仅 D4/D5/D6 下降 ≥2 分而 D1/D2/D3 稳定 → **可关闭推理**，但把退化点记入待办（属可接受退化，见 §8）。

**幅度为何定"1 分"**：盲评噪声通常 ≤1 档；核心三维各降 ≤1 分可视为"质量持平"；任一心降 ≥2 分意味着实质能力塌陷，不是噪声。

### 7.4 样本口径与适用范围（对齐 E2 的 N=24 方案）
**先澄清两种口径（含义不同，不得混用）**：
- **口径一：不同输入各评 1 次**（跨样本）。
- **口径二：同一输入重复多次**（如 1 组 ×3 runs，同输入）。

**本实验实际样本构成（与 E2 对齐）**：**N = 24**，由两层组成——
- **2 组内容独立的真实锚点**（真实简历 × 岗位）：taskId **22** 与 taskId **6 或 11 中之一**。**taskId 6 与 11 的 `jdText`/`resumeJson` 完全相同、内容等价，仅元数据 ID 不同，只按 1 组计**（避免伪重复虚增真实侧样本量）。
- **22 组"以真实为模板的受控局部扰动"合成输入**，分四层、每层 6 组（真实位由 3 组修正为 2 组后，少掉的 1 个位用合成补齐）：
  - **S1 强匹配 / S2 弱匹配 / S3 歧义 / S4 边界对抗**（按 `localResult` 规则覆盖度**客观判定**分层）。
- 配 **K7 真实锚点护栏**（见下）。

**口径结论**：
- **采用口径一（跨样本、各评 1 次）**：24 组样本覆盖 4 个难度层，**但独立观测数受输入模板数封顶**（见下"独立性限定"）。
- **口径二（同输入重复）仍不可作放行依据（此结论不变）**：`temperature=0.1` 下同输入重复输出高度接近（近确定性），**无法提供输入多样性信息**、覆盖不到长尾与难度分层；只能算"同输入一致性检查"，不得替代跨输入覆盖。

**独立性限定（"不同输入" ≠ "独立观测"，重要）**：独立观测数受**内容互不相同的输入模板数**约束；**不同输入若其输出逐字相同，不构成独立观测**。本次实测：30 份输出仅 **23 份**为不同逐字文本、**7 组逐字全同（合计 14 份重复）**；15 个盲评单元按 `(resumeJson + jdText)` 去重后**仅 7 个不同输入模板**。即**输入模板数与输出唯一文本数均远小于样本数**，故"24 组样本 = 24 个独立观测"**不成立**，统计判决的独立性前提受限；有效样本量 `N_eff` 由实验设计者按 **E2 §7.9.1** 计算。本条**不改变 §7.1 合格线**，只约束统计结论的解释口径（避免把样本数误读为独立观测数）。

**外部效度限制（必须写进结论）**：22 组合成为"以真实为模板的受控扰动"，**其分布不代表真实简历/岗位的自然分布**。故结论只对"该合成分布 + 2 组内容独立的真实锚点"成立，**不得**外推为"对所有真实岗位/简历类型安全"；对外发布的口径须以 **2 组内容独立的真实锚点**为最终依据。

**真实侧样本量与最终防线**：**内容独立的真实锚点仅 2 组**（taskId 22、taskId 6/11 之一），无独立统计余量——故**真实侧的最终防线是 K7 真实锚点护栏**（任意真实锚点 R_off 比 R_on 差 > **δ_eff = 8 分**，或触发契约/接地/注入护栏 → **阻断全局关闭**），而非样本量本身。本 Rubric 的 §7.5 只做单样本层面的"明显退化"快速拦截；统计判决（K4 非劣性检验、inconclusive → 默认 KEEP）以 E2 为准。

### 7.5 实质性退化闸（单向阈值，先于 §7.3 执行）
默认动作是"不改"（继续开启推理）；但**只在"关推理出现实质性退化"时才拦截**，持平与更好一律放行。

**口径（臂均值，勿按单样本读）**：记 `ΔTotal = mean(Total_off) − mean(Total_on)`、`Δdᵢ = mean(dᵢ_off) − mean(dᵢ_on)`，其中 `mean(·)` 取该臂在**全部评测单元**上的均值。**触发本闸的 `Δ` 一律为臂均值。**

> **仅当 `ΔTotal ≤ −8` 分 或 任一维 `Δdᵢ ≤ −2` 分时，判「实质性退化」→ 维持现状（继续开启推理）。**
> **其余情况（含两臂持平 Δ≈0、以及关推理更好）不在此拦截，进入 §7.3 判定。**

> **单样本黄灯（与臂均值区分）**：某**单样本**某维差达 2（如 E4 实测 `u-7f28…` 的 D3：3 vs 5）→ 记为**黄灯**，须在回传中**显式列出**，但**不单独触发本闸**（否则单点噪声即拦截）；若该单点同时伴随契约/接地/注入异常 → **升级为阻断**（与 E2 单点护栏一致）。

**X = 8、Y = 2 的定值依据（依评分刻度）**：
- **Y = 2** = 单维度"整档"阈值（相邻锚点间距为 2）。任一维出现 ≤ −2 的差异，即视为**超出评审噪声**（呼应 §7.3"任一心降 ≥2 = 实质塌陷非噪声"）。
- **X = 8** ≈ 最重维度 D1 单档摆幅的 1.3 倍。D1 权重 30，单档 = 30 × 1/5 = **6 分**；含义是总分差不足以超过"一个核心维度整档左右的漂移"时，不视为实质退化。反之 D1 降 2 档（−12）或 D1+D2 各降 1 档（−11）均 ≤ −8，会正常命中本闸。

**为什么是单向、而非"证据不足即维持"**：本实验按**非劣性检验**定义（见 E2）——H0：关推理至少差一个边际 δ（**δ_eff = 8 分**）；H1：关推理非劣。在非劣性框架下，**"两臂持平（Δ≈0）"是理想结果**（明显大于 −δ_eff，正当拒绝 H0），不应被误判为失败。对称阈值会把绝大多数"两臂接近"的情形预先锁死为"维持现状"，**等于让结论失去下结论的能力**；故本闸只做**退化方向的拦截**。

> **权威数值对齐（E1 × E2）**：`δ_eff`（E2 非劣性边际）= **8** 与 `X`（本 §7.5 总分实质退化阈）= **8** 在 **−8 处精确对齐**——本闸在 `ΔTotal ≤ −8` 时拦截，E2 判非劣要求效应下界 `> −8`。二者相等即**无缝隙**：不会出现"E1 放行但 E2 判非劣不成立"的情形。若任一值被改动，两者必须同步改，否则会漏出一条缝隙。

**与 E2 的关系（不重复兜底）**：小样本的功效弱点由 E2 既有机制负责，本 Rubric **不另设统计兜底**：
- **K4**：非劣性检验未拒绝 H0（含 CI 横跨 −δ_eff，即 −8 的 inconclusive）→ **一律默认 KEEP**（统计上正确的护栏）。
- **K7 真实锚点护栏**：**2 组内容独立的真实输入**（taskId 22、taskId 6/11 之一）中任一 R_off 比 R_on 差 > **δ_eff = 8 分**，或触发契约/接地/注入护栏 → **阻断全局关闭**。
本 §7.5 只提供**单样本层面的"明显退化"快速拦截**，统计判决以 E2 为准。

**判定顺序（与 §7.3 合成）**：
- **第 0 步（本闸）**：命中 `ΔTotal ≤ −8` 或某维 `Δdᵢ ≤ −2` → **维持现状**。
- **第 1 步（§7.3）**：未触发本闸 → 按 §7.3 判：R_off 过 §7.1 且核心三维无 ≥2 降 → **可关闭**（仅非核心降则记待办）；R_off 未过 §7.1 → **不可关闭**。

## 8. 关键区分：哪些退化可接受、哪些不可接受

**不可接受的退化（一旦出现，判"不可关闭推理"）**：
- 事实忠实度下降 → 出现幻觉（V1）；
- 引用精度下降 → `quote`/`evidence` 失真或不存在（**V2a 仅模式 R；V2b `evidence` 层两模式均生效**；模式 P 下 `quote` 非空比例的两臂差异只作佐证，见 §2 D3）；
- JD 覆盖度下降 → 遗漏硬性要求、`status` 误判；
- 可操作性下降 → 建议退化为套话（K1 成片）；
- 置信度校准下降 → 证据弱却给高置信。

**可接受的退化（关闭推理后允许，记待办即可）**：
- `summary` 的精炼度/措辞、`readabilityRisks` 的细腻度；
- 输出条数减少（如 findings 5→3），只要核心覆盖仍在；
- 表述文采、过渡语、排版美观度。

**理由**：退化是否可接受，只看它是否侵蚀产品的存在理由——"**有据（引用可查）+ 有覆盖（对得上 JD）+ 有行动（能照着改）**"。侵蚀这三点即不可接受；只是变朴素、变短、变不好看，则可接受。

## 9. 评分者输出格式（必须逐项给出"因为 X 所以 Y 分"）

对每份输出，输出如下结构化结论：

```
【评分对象模式】模式 P / 模式 R（由裁决者指定；决定 V2 是否生效）
【被评对象】输出 A / 输出 B（匿名）
【维度分】
D1 事实忠实度：X/5 —— 因为 <引用具体字段与原句>，所以 X 分
D2 覆盖完整度：X/5 —— 因为 <硬性要求覆盖情况 / status 与证据是否自洽>
D3 证据可核查性：X/5 —— 因为 <quote 非空率 / 逐字回溯结果>
D4 可操作性：X/5 —— 因为 <具体动作举例 vs 套话举例>
D5 结论与置信度：X/5 —— 因为 <summary 与明细是否一致 / 置信是否贴合>
D6 可读性风险：X/5 —— 因为 <风险项是否指向真实问题>
【扣分】K?: 每条一行"因为 <具体项> 所以扣 <N> 分"，并给合计
【否决】V1/V2a/V2b/V3 命中情况（命中即列出证据原文与对应断言；模式 P 下 V2a 记 N/A、V2b 仍判）
【规则侧疑点】列出"AI 判 MISSING/PARTIAL 但简历原文实有"的关键词 + 简历原文出处；注明疑似规则引擎同义词误报，**不计入 AI 扣分**，转贝洛奇核实
【加权分】Σ(d×w÷5) = …；【总分】= 加权分 − 扣分 = …
【单份结论】PASS / REVIEW / FAIL
```

两份都评完后，按 **§7.3 + §7.5** 给出**【关闭推理裁决】**：可关闭 / 不可关闭 / **证据不足（维持现状）** / 需复核，并写明依据 §7.1–§7.5 的哪一条。

## 10. 执行流程（机械步骤，照做即可）
1. 取得四件套输入（简历原文、JD 原文、输出A、输出B）+ 裁决者指定的**评分对象模式（P / R）**，缺件或缺模式即停。
2. 对 输出A：逐维按 §2 锚点定分 → 做 §6 否决扫描（命中即标记 fail，但仍完成各维打分以留证；模式 P 下 V2a 记 N/A、V2b 仍判）→ 做 §5 扣分计数 → 算总分 → 出 §9 结论。
3. 对 输出B：重复第 2 步。
4. 揭盲（由裁决者确认哪份开了推理），按 **§7.3 + §7.5** 出裁决（含"证据不足 → 维持现状"分支）。
5. 全程不参考任何"哪份关了推理"的提示；评分依据只允许来自简历原文、JD 原文、两份输出本身。

## 11. 反作弊护栏（评分者自检）
- 不得因**输出更长、条目更多**而加分；长度不是质量。
- 不得因**措辞更漂亮**而抬高 D1/D2/D3；这三维只看可核查的事实。
- 不得用"整体感觉不错"替代逐维证据；无证据的分视为无效分，须重评。
- 若两份输出难分伯仲（分差未触发 §7.5 单向退化闸，即**持平**）→ 如实判"质量持平"，**不得**为制造差异而凑分；持平按 §7.3 **放行**（§7.5 只拦截"关推理明显更差"，不拦截持平）。
- 发现输出疑似"堆砌通用内容充数"（K1/K3 成片）→ 严格按 §5 扣分，不因"至少写了"而留情。
