## 2. 目标与方法

**目标**：判断能否把 ATS 语义分析也关掉模型推理 —— 生成任务关推理后从 477s 降到 7s（ADR-005），若 ATS 同理可省下 20–30 倍耗时。

**方法：预注册的非劣性检验**（全部在取数**之前**冻结）：

| 要素 | 内容 |
| --- | --- |
| 唯一自变量 | 请求体是否含 `enable_thinking: false`（其余逐字节相同，`request_sha256` 自证） |
| 固定项 | 模型 `qwen3.8-max`（不走模型链、无顺延）、`temperature=0.1`、同一 prompt（由任务快照精确重建） |
| 边际 | `δ_eff = 8`（满分 100，锚定 E1 的 X=8，`−8` 处对齐无缝隙） |
| 判据 | 单侧 α=0.05 非劣性检验 + bootstrap 90% CI；K1–K9 护栏；**预先登记的三种互斥结局** |
| 评分 | 独立评分者按 E1 rubric **双盲**评分；评分对象 = **原始输出**（保留被校验器抹掉的信号）；v1.3 为唯一权威版本 |
| 样本 | 计划 N=24（3 真实 + 21 受控扰动合成，四层各 6）；**实际执行 Stage 1 = 8 样本 + 4 twin** |

**护栏设计要点**（值得复用）：δ 三档敏感度（防单点失效）、twin 负对照（噪声底 + 位置偏置）、硬隔离未通过校准的裁判数值、`N_eff` 去重门禁、K9 测量饱和护栏、单点黄灯协议。

## 4. 为什么没能回答问题

三层原因，按重要性：

**① 测量分辨率与决策边际不匹配（最本质）**
`real-6` 与 `real-11` 的 `resumeJson`/`jdText` **逐字相同**（仅元数据 ID 不同），配对差却分别是 **−10 与 −3，相差 7 分**。即**输入层配对差噪声 ≈7 分，而 `δ_eff` 仅 8 分** —— 边际与噪声同量级，量具几乎无分辨力。

**② 评分量表近天花板**
分数压在 88–100、D1 几乎全 5 分 → 工具在该量程内难以区分。K9 虽因 Arm N 均值 93.625 未达 >95 而未触发，但近饱和已记录。

**③ 副裁判路线在本环境不可行**
- `qwen3.8-27b`（同源）：`T_L = 14.714`（阈值 5.357）**不通过**；且**veto 身份跨 rubric 版本不一致** → 否决不可复现；
- `glm-5.3`（异源）：twin-only 14 发**5 发撞 1200s 超时（36%）**，**丢光全部 3 组真实锚点对** → 仅 3/7 存活、`T_L=0.0` 是**易子集伪影，校准闸未真正执行**。

> ⚠ 与预注册的背离（诚实记录）：E2 §7.9.4 曾预估"`N_eff` 很可能 < `N_req` → 结局 ③ 概率高"。**实测未成立** —— `N_req = 2`、`N_eff = 8`，**功效门通过**。本次落入 ③ 的成因是**测量工具与分辨率**，不是样本量。

## 5. 副产品（本轮真正的收益）

**① 一个可排期的生产缺陷（E3-F1，已立案）**
`app.scoring.synonym-dictionary` 配置存在但**运行时未生效**（按空词典行为）→ 多词关键词（如 `Spring Boot`）因 tokenizer 按空格切词而**必然判 MISSING** → **关键词覆盖度被系统性低估**（实测 60 应为 80、20 应为 40）。即**用户看到的 ATS 规则分比其应得的更低**。
- 影响面已收敛：**不传导到 AI 输出层**（评分者逐字核验：AI 在 Spring Boot 确实存在时多数正确判 MATCHED）→ 污染的是规则分展示，不是 AI 判断质量；
- 本轮**刻意冻结不修**（保实验基线），已在 `docs/decisions/OPEN-DECISIONS.md` 立项。

**② 一条可复用的裁判基础设施陷阱**
**长输出评测的延迟与臂别耦合** → 高超时率裁判的"存活子集"本身有偏；且本例是**近随机超时丢光了全部真实锚点对**。下一轮必须把"超时按样本/按臂的分布"作为前置门禁。

**③ 三条测量工具的反证**
`T_L=0.0` 看似完美实为伪影（易子集）；同一裁判换 rubric 版本 **veto 身份就变**；输入层噪声 ≈δ。三者共同说明："未检出差异"与"已证明等价"之间的距离远比通常估计的大。

**④ 一组可复用的实验纪律**
硬隔离未过校准的工具数值（`mean(N−R)=−13.75` 极易被误读成"关推理差 13.75 分"而实为噪声）；预注册否证条件与"inconclusive → 维持现状"；对称性裁断（工具不可靠时其数值两个方向都不可用）。

## 6. 第二轮的必要条件（三件必须一起做）

1. **两名预注册的独立 agentic 评分者** —— 互不可见、均不参与 rubric 与 harness 编写；事前登记一致性判据（ρ / pass-fail 一致率 / twin 负对照）。
2. **内容互不相同的真实锚点** —— 本次真实锚点仅 2 个内容独立样本、且其中一对还是同一内容，导致红线判定缺独立观测。
3. **重估 `δ` 与量表** —— 若输入层噪声就在 7 分，`δ=8` 无分辨力：需**增样本 + 缩 δ**，或改用能脱离 88–100 天花板的更灵敏量表。

> ⚠ **不可只换裁判**。只修第 1 项会让第二轮重演同样的结局 ③。

**不依赖实验的短期缓解**（当前 ATS 仍然慢，且 600s 超时尾部未消除）：可先做超时尾部治理与可用性兜底，此事项独立于质量结论。

## 7. 过程发现（编排层，比技术缺陷更易拖死项目）

**① 跨文档语义漂移出现 5 次** —— `δ_eff` 声明值与残留公式冲突；`Δ` 未写明单样本还是臂均值；§7.3 与 §7.5 对"单点差 2"结论相反；"默认动作"三种读法（§0/§7.9.4/E1）；§7.6 与修正后 §0 再冲突。**共同病根：同一符号/术语没有单一权威定义。** 这类缺陷不会让任何单份文档"看起来有错"，只在有人按字面实现或把两份并排读时暴露。→ 对策：术语表 + **实现者按磁盘版本核对**（team-lead 已停止转述数值阈值）。

**② team-lead 自身 3 次同类错误** —— 把"参数兼容性探测"外推成"模型不可用"；把一次可用性探测直接当运维事实转述；**从两个现象拼出因果链（超时∝输出长度∝臂）当事实写入文档，被逐条数据驳回且方向相反**。三次都是"从看起来合理直接跳到是"。→ 对策（已落为流程约束）：**凡声称驱动因素的结论，落文档前必须给出逐条数据或反例检索结果。** 同时**拒绝**了把它做成"自动反例扫描"的提议（失效形态不可枚举、误报代价高）—— 属过度设计。

**③ 串行阻塞** —— team-lead 把"必须等 v1.3 分数冻结"设为前置条件，导致评分者停摆 3 小时时**整条链路停摆**。→ 对策：下游应在**标注前提**下先行推进（本次以"v1.2 预演 + 版本差异表"解锁）。
