## 7. 关键代码骨架

### 7.1 DTO

```java
public record ConfirmRequest(
    @NotNull LocalDateTime taskUpdatedAt,        // 乐观锁
    @NotEmpty @Size(max = 200) List<ConfirmedDraftItem> items,
    Map<String, Object> additionalResumeJson      // 用户主动新增事实(可选)
) {}

public record ConfirmedDraftItem(
    @NotBlank String outputPath,                 // "work[0].highlights[2]"
    @NotNull Decision decision,                  // ACCEPT / EDIT / REJECT
    Map<String, Object> editedValue              // 仅 decision=EDIT 时必填
) {}

public enum Decision { ACCEPT, EDIT, REJECT }

public record ConfirmResponse(
    Long resumeVersionId,
    Integer versionNo,
    Long resultResumeVersionId,
    List<Long> rejectedPaths,
    List<Long> newMaterialIds
) {}

public record RejectRequest(@NotNull LocalDateTime taskUpdatedAt) {}
```

### 7.2 ResumeJsonNormalizer

```java
@Component
public class ResumeJsonNormalizer {

    // 输入:草稿 JSON(含 _source / _pending)
    // 输出:标准化 JSON(剥掉 _source / _pending,保留业务字段)
    // 规则:
    //   - 遇到 _source:保留其下所有字段;剥掉 _source
    //   - 遇到 _pending:抛 INVALID_PATH 或 BUSINESS(REQUIRE_USER_INPUT),
    //     除非该项的 decision=ACCEPT 且 require-explicit-source=false(本卡不允许)
    //   - 未出现在 items 中的 _pending 一律拒绝提交
}
```

### 7.3 DraftCommitService

```java
@Service
public class DraftCommitService {

    @Transactional
    public CommitResult commit(AiTask task,
                               List<ConfirmedDraftItem> items,
                               Map<String, Object> additionalResumeJson,
                               Long userId);

    public record CommitResult(Long resumeVersionId, Integer versionNo,
                               List<Long> newMaterialIds) {}

    // 实现要点(必须在同一事务中):
    // 1. SELECT ai_task ... FOR UPDATE 锁定任务(防止并发确认)
    // 2. 校验 task.status == SUCCESS && task.confirmationStatus == PENDING
    // 3. 校验 task.userId == userId(否则 NOT_FOUND)
    // 4. 校验 taskUpdatedAt == ai_task.updated_at,否则抛 40901
    // 5. 解析草稿 result_json 抽取 selectedMaterials(每个含 materialId, outputPath)
    // 6. 对每个 ConfirmedDraftItem:
    //    - 若 path 不在 selected 中:抛 INVALID_PATH
    //    - decision=REJECT:在 normalized JSON 中跳过该字段;记录 rejectedPaths
    //    - decision=EDIT:用 editedValue 覆盖字段;若 editedValue 含未声明事实(无 _source):
    //        - 走 career_material 新增(UsagePreference.NORMAL, sourceText=原 editedValue 文本);
    //        - 记录 newMaterialIds;
    //        - 但 normalized JSON 中该字段仍写入(因为用户已显式确认)
    //    - decision=ACCEPT:原样接受
    // 7. 调用 ResumeVersionService.createInTransaction(resumeId, sourceType=JD_CUSTOMIZED, normalizedJson, summary, generationContextJson=任务 input_snapshot_json + result_json 摘要)
    // 8. 写 resume_material_reference(每个 selected.materialId → resume_version_id, selectionStatus=SELECTED, source_snapshot_json=读时的 CareerMaterial 快照)
    // 9. 更新 ai_task.confirmationStatus=CONFIRMED, confirmed_at=now, result_resume_version_id=newVersionId(利用 UNIQUE 约束防重复)
    // 10. 提交事务
}
```

### 7.4 ConfirmationService

```java
@Service
public class ConfirmationService {

    public ConfirmResponse confirm(Long taskId, ConfirmRequest req, String idempotencyKey, Long userId);
    public void reject(Long taskId, RejectRequest req, Long userId);

    // confirm 实现要点:
    // 1. 校验 idempotencyKey 非空
    // 2. 读取 AiTask(跨用户返回 NOT_FOUND)
    // 3. 若 ai_task.confirmationStatus=CONFIRMED 且 result_resume_version_id 非空:
    //    校验 idempotencyKey 是否已记录(若无,使用 ai_task.id 作为幂等键);返回已存在的版本
    // 4. 否则调用 DraftCommitService.commit
    // 5. 写入 idempotency 表或利用现有 ai_task.id 字段做幂等

    // reject 实现要点:
    // 1. 校验 task 与 userId
    // 2. 校验 task.confirmationStatus == PENDING
    // 3. 更新 confirmationStatus=REJECTED, 不创建 resume_version
}
```

> 幂等表本卡**不新建**(会破坏"不改表"原则);幂等键记录在 `ai_task.idempotency_key` 字段。MVP 允许:同 task 的 confirm 重放永远走"已 CONFIRMED"分支返回原版本。

### 7.5 Controller 路由

| 方法 | 路径 | 说明 | 必填 |
| --- | --- | --- | --- |
| POST | `/api/ai/tasks/{id}/confirm` | 用户确认 | Header `Idempotency-Key`, Body 含 `taskUpdatedAt` |
| POST | `/api/ai/tasks/{id}/reject` | 用户拒绝 | Body 含 `taskUpdatedAt` |

### 7.6 关键不变量

- **不批量确认 AI 自行生成事实**:前端必须按 item 单项操作(参见 §8)
- **乐观锁**:`taskUpdatedAt` 与 `ai_task.updated_at` 不一致 → `40901`
- **并发冲突**:`SELECT FOR UPDATE` + `result_resume_version_id UNIQUE` 共同保证只创建一个版本
- **跨用户**:返回 `40401`,不暴露任务存在性
- **资源软删追溯**:`source_snapshot_json` 在 commit 时复制 `CareerMaterial` 全部字段(即使后续被软删,历史快照仍可读)
- **AI 不可信事实不可直接采纳**:若用户未在 items 中显式 ACCEPT/EDIT,`_pending` 字段不会进入 normalized JSON
- **拒绝幂等**:同 idempotencyKey 重放 reject 返回相同结果(本卡:不创建任何版本)

**UI 最小要求**(`13 §5 T08` + `13 §6`):

1. 草稿页右侧展示 `_source` 与 `_pending` 两类标记:
   - `_source`:链接到原始资料,显示「来源:工作经历 #10」,可一键跳转
   - `_pending`:标红,显示「待用户补充/确认」
2. 每条 item 提供三按钮:**接受** / **编辑** / **拒绝**;不允许一键全选
3. 顶部展示任务状态(PENDING/RUNNING/SUCCESS/FAILED)、刷新时间、确认按钮 disable 直到所有 `_pending` 项均有决策
4. 「编辑」打开模态框,提交后保存为 `editedValue`;若内容超出资料范围,前端提示「将作为新事实记录」
5. 「拒绝」仅隐藏该字段
6. 提交时使用 `Idempotency-Key = taskId + "-" + currentTimestamp`,并把 `taskUpdatedAt` 一并发送
7. 乐观锁冲突(`40901`)时,展示「任务已被其他操作修改,请刷新」并自动重新拉取
