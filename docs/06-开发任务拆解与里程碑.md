# 开发任务拆解与里程碑

## 1. 使用说明

本文件用于将项目开发工作落到可执行任务上，适合用作：

- 实际开发排期
- 看板拆分
- 版本迭代管理
- 每周推进跟踪

## 2. 总体原则

- 以主流程闭环为优先
- 以 P0、P1、P2 管理优先级
- 以阶段为主线，避免过度并行开发

## 3. 第一阶段：基础系统

### 3.1 后端任务

P0：

- 初始化 Spring Boot 工程
- 统一返回结构与全局异常处理
- JWT 鉴权框架搭建
- 用户注册/登录/刷新/退出接口
- 登录和 AI 请求的基础限流、配额和审计日志
- 用户表设计与落库
- 简历表与简历版本表设计
- 简历 CRUD 接口

P1：

- 参数校验规范
- 通用日志拦截
- 基础错误码体系

### 3.2 前端任务

P0：

- 初始化 Vue 3 工程
- 登录页面
- 注册页面
- 首页骨架
- 简历列表页
- 简历编辑页

P1：

- 表单校验
- 基础状态管理
- 通用请求封装

### 3.3 第一阶段验收

- 用户可注册并登录
- 令牌刷新和退出登录生效，越权访问与频率超限被拦截
- 可创建和编辑简历
- 简历可保存到数据库

## 4. 第二阶段：MVP 求职闭环

### 4.1 后端任务

P0：

- 职业资料表和简历资料引用表设计
- 职业资料 CRUD 接口
- JD 表设计
- JD CRUD 接口
- JD 关键词解析逻辑
- 基于 JD 的职业资料筛选与岗位定制简历生成接口
- Spring AI 接入
- AI 任务表设计、同意校验、幂等键、用户配额和异步状态查询
- 匹配评分服务实现
- 导出任务、私有文件下载与过期清理

P1：

- Prompt 模板管理策略
- AI 错误重试与失败记录
- 匹配结果持久化

### 4.2 前端任务

P0：

- 职业资料库管理页
- JD 输入页
- JD 列表页
- 基于岗位生成简历入口与资料选择理由展示
- 版本历史页
- 匹配评分展示页
- 异步任务状态、结果确认和失败重试界面
- 单模板导出入口与受控下载

P1：

- 原文、生成草稿与确认版本对比展示

### 4.3 第二阶段验收

- 用户可维护职业资料并输入 JD
- 系统可按 JD 筛选资料并生成岗位定制简历
- 用户可确认来源可追溯的草稿并保存新版本
- 系统可返回基础匹配评分并导出私有 PDF

## 5. 第三阶段：求职质量与投递体验

### 5.1 后端任务

P0：

- 零碎资料导入任务和待确认资料写入
- 实时优化、成果量化引导和 ATS 体检
- 求职沟通文案生成
- 投递记录、状态历史和状态迁移校验

P1：

- 多模板预留设计

### 5.2 前端任务

P0：

- 待确认资料、实时优化和 ATS 体检界面
- 求职沟通文案编辑和投递看板

P1：

- 多模板预览、投递状态筛选交互

### 5.3 第三阶段验收

- 用户可将零碎资料确认并复用
- 用户可获得 ATS/量化建议、生成文案并管理投递状态

## 6. 第四阶段：AI 面试与工程增强

### 6.1 后端任务

P0：

- Redis 缓存接入
- 热点数据缓存
- 平台简历 AI 面试会话、轮次、报告和答案资产
- 外部简历文本面试

P1：

- RocketMQ 或 RabbitMQ 接入（任务规模需要时）
- 链路追踪
- 监控指标采集

### 6.2 前端任务

P1：

- 任务轮询状态优化
- 操作反馈增强
- 错误提示细化
- 多轮面试和报告页面、答案资产复习

### 6.3 第四阶段验收

- 用户可完成 AI 面试、查看报告并沉淀答案资产
- 系统具备异步、监控和工程增强能力

## 7. 推荐周计划

### 第 1 周

- 后端骨架
- 前端骨架
- 用户与简历基础能力

### 第 2 周

- 简历编辑闭环
- 简历版本管理
- 职业资料库管理
- JD 管理

### 第 3 周

- Spring AI 接入
- 岗位定制生成任务与用户确认
- 评分逻辑初版

### 第 4 周

- 生成结果确认页
- 评分结果页
- 联调与问题修复

### 第 5 周

- PDF 导出
- 单模板渲染与私有下载

### 第 6 周

- 回归测试
- 文档补齐
- 性能与异常处理优化

## 8. 当前最优执行顺序

建议按下面顺序落地：

1. 认证
2. 简历
3. 版本
4. 职业资料库
5. JD
6. 岗位定制生成
7. 基础评分与私有 PDF 导出
8. 成果量化、ATS、实时优化和零碎资料导入
9. 沟通文案与投递管理
10. AI 面试与答案资产
11. 缓存、监控与进一步异步化

## 9. 风险提醒

- 不建议一开始就做 MQ 和微服务
- 不建议同时推进太多前端页面
- 不建议过早追求复杂匹配算法
- 不建议在主流程未稳定前大量优化 UI 细节
