# MVP 实施契约与任务卡

## 1. 用途

本文件把 M1/M2 拆成低能力代码代理可以机械执行的行为切片。代理不得自行改变顺序、扩展范围或补充契约。若本文件与 `01` 至 `10` 冲突，以 `01` 的范围、`02` 的业务规则、`04` 的数据结构和 `05` 的接口契约为准，并按 `12` 停止报告。

## 2. 固定技术决策

- 后端：Java 17、Spring Boot 3.3.x、Spring Security、Spring Data JPA、Flyway、MySQL 8.4。
- 前端：Vue 3、TypeScript、Pinia、Axios、Vue Router、项目 CSS、`lucide-vue-next`。
- AI：Spring AI 适配层；生产提供商必须由单独 ADR 批准，测试使用确定性 Mock Provider。
- MVP 异步：MySQL 持久化任务 + 应用内后台工作器 + 前端轮询；不使用 Redis、MQ、RAG、向量库或微服务。
- PDF：Node.js/Puppeteer 私有服务，只接受结构化 JSON 和固定 `classic` 模板。

## 3. 全局不变量

每张任务卡都必须满足：

1. 除公共白名单接口外，默认鉴权。
2. 所有资源查询和写入均由认证上下文取得 `userId`，请求体不得指定资源所属用户。
3. 所有子资源沿父链校验归属；跨用户访问按统一策略返回资源不存在。
4. AI 不生成或一键确认资料库外的事实、技能、数字或成果。
5. 写接口定义参数校验、成功响应、错误码、幂等或并发语义。
6. 任务、版本、来源和文件访问都可追溯，不打印敏感原文。
7. 每个行为切片先写失败测试或建立明确的现状基线，再实现，再执行验证命令。

## 4. 任务依赖图

```text
T01 基础数据库与迁移
 ├─ T02 认证会话
 ├─ T03 简历与版本
 ├─ T04 职业资料
 └─ T05 JD
T02 + T03 + T04 + T05
 └─ T06 AI 同意与任务框架
     └─ T07 岗位定制生成
         └─ T08 来源确认与版本落地
T03 + T05
 └─ T09 JD 规则覆盖度
T03
 └─ T10 私有 PDF
T02-T10
 └─ T11 MVP 端到端验收
```

任何代理一次只领取一张任务卡。T01 至 T11 必须按依赖顺序推进。

## 5. 任务卡

### T01 基础数据库与迁移

- 目标：接入 JPA、Flyway 和 MySQL，创建 M1/M2 必建表。
- 来源：`03 §6.2`、`04 §2.1`、`04 §8`。
- 允许范围：`server/pom.xml`、数据库配置、Flyway 迁移、实体公共基类、迁移测试。
- 禁止：业务 Controller、Redis、MQ、路线图表。
- 验收：空数据库迁移成功；重复启动不重复建表；表、索引和唯一约束与 `04` 一致；迁移失败阻止应用启动。
- 验证：`Set-Location server; mvn test`。

### T02 认证会话

- 目标：完成注册、登录、刷新轮换、当前用户和退出登录。
- 来源：`02 §5.1`、`04 §3.1/3.1.1`、`05 §2`、`07 §5.1`。
- 允许范围：auth 模块、security 配置、auth DTO/实体/仓库/测试。
- 禁止：简历、AI、PDF。
- 必测：重复用户名/邮箱、错误密码、未登录、刷新成功、旧令牌复用撤销令牌族、当前退出、全部退出、Cookie 属性、限流。
- 完成定义：不保存或记录明文刷新令牌；所有测试通过。

### T03 简历与版本

- 目标：完成简历 CRUD、手动版本、版本历史和当前版本切换。
- 来源：`02 §5.2/5.3`、`04 §3.3/3.4`、`05 §4/§5`。
- 必测：本人 CRUD、跨用户、软删、版本号并发唯一、历史版本不可修改、无效 JSON Resume。
- 禁止：AI 自动创建版本。

### T04 职业资料

- 目标：完成资料 CRUD、类型过滤和引用偏好。
- 来源：`02 §5.5`、`04 §3.2`、`05 §3`。
- 必测：空列表、类型过滤、PREFERRED/EXCLUDED、软删、跨用户、资料被历史快照引用后仍可追溯。

### T05 JD

- 目标：完成 JD CRUD 和确定性规则解析。
- 来源：`02 §5.4`、`04 §3.5`、`05 §6`。
- 必测：原文保留、重复解析覆盖解析结果但不覆盖原文、空文本、超长文本、跨用户和软删。
- 禁止：在本任务调用大模型。

### T06 AI 同意与任务框架

- 目标：完成 AI 同意、数据库任务、幂等、抢占、租约、重试和状态查询。
- 来源：`02 §7.3`、`03 §9.5/9.6`、`04 §3.1.2/3.8`、`05 §2.6/§7.5`。
- 必测：未同意不创建、撤回后不创建、相同幂等键返回原任务、相同键不同请求冲突、工作器重启恢复、租约过期、最大重试、跨用户任务查询。
- 禁止：真实外部 AI；使用 Mock Provider。

### T07 岗位定制生成

- 目标：基于资料 + JD 生成结构化草稿、来源映射、未选理由和缺失项。
- 来源：`02 §5.6`、`03 §5.6`、`05 §7.1`。
- 必测：固定/优先/排除覆盖模型选择；资料不足；模型输出格式错误；Prompt Injection；跨用户资料 ID；每个输出路径有来源或待主动补充状态。
- 禁止：直接创建 `resume_version`。

### T08 来源确认与版本落地

- 目标：用户逐项接受、编辑或拒绝草稿，并事务性创建唯一版本。
- 来源：`02 §5.6`、`04 §3.6/3.8`、`05 §7.6`。
- UI 最小要求：每个生成要点显示来源片段、改写差异、验证状态和单项操作；不得用一个按钮批量确认 AI 自行生成事实。
- 必测：双击确认、两标签页并发、相同幂等键重放、任务已更新冲突、来源被软删、用户主动新增事实、跨用户确认。

### T09 JD 规则覆盖度

- 目标：计算关键词、技能和经历规则覆盖，并保存规则版本和证据。
- 来源：`02 §5.13`、`04 §3.7`、`05 §10`。
- 用户文案：统一称“JD 规则覆盖度”，固定展示“非企业 ATS 结果、非录用概率”。
- 必测：空 JD、空简历、大小写/同义词、重复关键词、极端关键词堆砌、规则版本和解释稳定。

### T10 私有 PDF

- 目标：用固定 `classic` 模板异步生成并受控下载 PDF。
- 来源：`03 §9.7`、`04 §3.16`、`05 §11`、`08 §8`。
- 必测：HTML 转义、外部 URL/文件 URL 被拒绝、超时、超大输入、临时文件清理、跨用户、过期、软删、校验和、服务认证失败。
- 禁止：模板选择器、任意 HTML、公开 URL。

### T11 MVP 端到端验收

- 目标：证明真实用户可完成资料库到私有 PDF 的完整闭环。
- 场景：注册登录 → 维护资料 → 创建 JD → 生成任务 → 页面重载恢复 → 逐项确认 → 查看规则覆盖度 → 创建 PDF → 下载。
- 必测失败场景：未授权、跨用户、AI 未同意、重复提交、提供商失败、工作器重启、资料不足、PDF 服务失败和文件过期。
- 完成定义：`02 §9.1`、`07 §9`、`09 §6/§7` 全部有测试或人工证据，无未解决 P0/P1。

## 6. 前端通用状态契约

每个异步页面必须实现：初始、加载、空数据、PENDING、RUNNING、SUCCESS、FAILED、CANCELLED、无权限和网络断开状态。轮询采用 1s、2s、4s、5s 封顶退避；任务 ID 持久化，重载后恢复。重试默认创建新任务并引用原输入快照，除非接口明确返回原任务。

不可逆操作必须有明确确认和结果反馈。所有状态变化提供文本和图标，不能只依赖颜色；主要流程支持键盘操作和 200% 缩放。
