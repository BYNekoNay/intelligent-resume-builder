# 部署与运维说明书

## 1. 文档目标

本文件用于规范项目在开发、测试、预发布、正式环境中的部署方式、运行依赖、配置管理、监控方案与故障处理方式。

## 2. 环境规划

### 2.1 开发环境

建议组成：

- 前端本地运行
- 后端本地运行
- 本地 MySQL
- 本地 Node.js 导出服务

用途：

- 单人开发
- 日常联调
- 快速排查问题

### 2.2 测试环境

建议组成：

- 前端部署实例
- 后端部署实例
- 独立 MySQL
- 独立文件输出目录

用途：

- 联调测试
- 功能测试
- 验收测试

### 2.3 预发布/演示环境

建议组成：

- 与正式环境接近
- 保留监控和日志
- 保留导出与 AI 配置

用途：

- 项目展示
- 面试演示
- 正式发布前验证

### 2.4 正式环境

建议组成：

- 前端 CDN 或 Nginx 静态资源
- 后端部署实例（含内嵌工作器）
- 独立 MySQL（主从可选）
- 独立 PDF 服务实例
- 独立文件存储目录

用途：

- 面向真实用户的生产服务

正式环境必须满足 §10.1 生产基线要求。

## 3. 部署结构建议

### 3.1 MVP 部署结构

```text
Nginx
├─ 前端静态资源
└─ 反向代理后端 API

Spring Boot API
├─ 业务主服务
└─ 内嵌工作器（数据库轮询线程池）

Node.js PDF Service
└─ Puppeteer 导出服务

MySQL
└─ 数据存储
```

MVP 阶段使用数据库轮询工作器（来源：03 §9.5），以内嵌线程池方式运行在 Spring Boot 应用内，不需要独立进程。工作器通过原子 SQL 抢占 PENDING 或租约过期任务；应用重启后，租约过期的 RUNNING 任务自动回到可重试状态。后续若任务量增长，可将工作器拆为独立进程（见 03 §7.2）。

### 3.2 后续增强结构

可在后续加入：

- Redis
- MQ
- Prometheus
- Grafana

### 3.3 网络分区

PDF 服务只监听私有网络接口（127.0.0.1 或内网 IP），不直接暴露给浏览器（来源：03 §9.7）。Nginx 作为唯一公网入口，反向代理后端 API。后端调用 PDF 服务走私有网络并携带轮换服务令牌。正式环境所有外部流量强制 HTTPS（来源：03 §9.8）。

## 4. 配置管理

建议区分以下配置：

- 数据库配置
- JWT 配置
- AI 提供商配置
- AI 数据处理同意版本、提供商地区和数据留存配置
- 用户、IP、任务类型的限流与配额配置
- 文件输出路径
- PDF 导出配置
- 日志级别

配置原则：

- 不在代码中硬编码密钥
- 环境间配置分离
- 敏感配置通过环境变量或外部配置文件传入
- 正式环境必须记录密钥所有者、轮换周期和最近轮换时间；轮换不得要求重新构建镜像

## 5. 启动顺序建议

建议顺序：

1. 启动 MySQL
2. 启动后端 API
3. 启动 PDF 服务
4. 启动前端页面
5. 检查接口连通性

## 6. 日志规范

建议至少保留以下日志：

- 应用启动日志
- 登录与鉴权异常日志
- AI 调用日志
- 职业资料筛选与岗位定制生成日志（仅记录任务、资料 ID 和结果状态）
- 评分执行日志
- ATS 体检、成果量化、沟通文案和投递状态变更日志
- 面试答案资产创建日志
- PDF 导出日志
- 全局异常日志

注意事项：

- 日志中不得打印密码、Token、敏感原文
- AI 请求体如包含简历原文，需避免完整打印
- 日志只记录提供商、模型、同意版本、任务类型、脱敏摘要和配额消耗，不记录完整资料、JD、面试回答或文案

## 7. 监控建议

### 7.1 基础监控

- 服务是否存活
- API 响应时间
- 错误率
- 认证失败率、限流命中率和 AI 配额消耗
- 导出成功率

建议阈值：

- API 健康检查：连续 3 次失败触发告警
- API p95 响应时间：超过 500ms 触发警告，超过 2s 触发严重告警
- 错误率（5xx）：超过 1% 触发警告，超过 5% 触发严重告警
- AI 任务成功率：低于 95% 触发警告
- PDF 导出成功率：低于 90% 触发警告
- 限流/配额拒绝率：超过 10% 触发信息级告警

### 7.2 增强监控

- AI 调用耗时
- 岗位定制生成成功率和资料选择耗时
- ATS 体检、成果量化和沟通文案生成耗时及失败率
- 投递状态变更失败率和答案资产创建成功率
- 导出耗时
- 任务队列积压情况
- 缓存命中率

## 8. 文件管理建议

- PDF 文件统一保存到固定目录
- 文件名建议带任务 ID、用户 ID、时间戳
- 存储键必须使用随机不可猜值，不得包含用户 ID、邮箱、姓名或简历标题
- PDF 文件生成后 24 小时自动删除，仅保留任务元数据和校验摘要（来源：04 §7.1）。
- 文件必须使用私有存储标识；仅通过受控下载或短时签名地址提供给资源所属用户

## 9. 故障处理建议

### 9.1 AI 调用失败

处理策略：

- 返回明确错误提示
- 保留错误日志和任务记录
- 支持重试
- 提供商不可用、用户未同意或配额不足时，明确返回不可执行状态，不发送用户内容

### 9.2 岗位定制生成失败

处理策略：

- 保留任务状态、JD ID 和资料选择上下文，避免记录完整敏感资料原文
- 返回可重试状态；资料不足时返回缺失项提示而非生成虚构内容
- 不覆盖用户资料和已有简历版本

### 9.3 ATS、沟通文案或成果量化失败

处理策略：

- 返回明确失败状态，保留可重试任务记录
- 成果量化未确认时不更新资料或简历；沟通文案失败不影响投递记录
- 日志不得记录完整简历、资料或沟通文案原文

### 9.4 PDF 导出失败

处理策略：

- 记录模板和渲染上下文
- 返回导出失败状态
- 可重新发起导出

### 9.5 数据库连接异常

处理策略：

- 启动时检查连接
- 运行时记录异常
- 及时阻断高风险写操作

### 9.6 数据删除与保留

处理策略：

- 资源删除先软删，再按保留期异步清理数据库记录和私有导出文件
- 历史版本和审计所需的上下文只保留不可编辑快照，禁止继续作为 AI 输入
- 账户删除任务应记录完成状态，失败时可重试并告警
- 职业资料、JD、简历主记录软删恢复期 30 天，恢复期结束后 7 天内硬删。AI 任务原始输入和结果完成 30 天后删除非必要内容。账户删除 7 天撤销窗口，窗口结束后 30 天内完成清理（来源：04 §7.1）。

## 10. 发布流程建议

建议流程：

1. 完成功能开发并同步数据库、接口、测试和运维文档
2. 执行单元、集成、端到端、安全和迁移测试
3. 生成不可变构建产物并记录版本
4. 备份数据库并验证最近一次恢复演练成功
5. 在测试环境执行 Flyway 迁移、启动检查和主流程验证
6. 记录回滚版本；迁移不兼容时禁止发布
7. 部署正式环境，验证 readiness/health、错误率和任务积压
8. 发布异常时回滚应用；数据库变更按迁移说明执行前向修复或已验证的回滚

### 10.1 生产基线

- Nginx 终止 TLS，启用 HSTS；MySQL、PDF 服务和管理端口不得暴露公网。
- 每日加密备份，RPO 24 小时、RTO 4 小时；至少每季度执行一次恢复演练。
- 后端和 PDF 服务必须配置 CPU、内存、并发和超时上限。
- 数据库、AI、PDF 和文件存储均需 readiness 检查；依赖不可用时阻止高风险写操作。

### 10.2 CI/CD 与容器化建议

建议使用 GitHub Actions 或 Gitee Go 实现基本 CI 流水线：推送触发 → 后端 mvn test → 前端 npm run build → PDF 服务 npm run check。MVP 阶段可使用 Docker Compose 编排本地和测试环境（项目根目录已提供 docker-compose.yml），但不作为正式部署的强制要求。Kubernetes 不在当前范围内（来源：01 §3.3）。

## 11. 运维检查清单

- 服务是否成功启动
- 数据库连接是否正常
- AI 配置是否有效
- 职业资料与岗位定制生成接口是否正常，且日志未暴露资料原文
- ATS、投递和面试资产接口是否正常，且无自动对外发送行为
- 导出路径是否可写
- 文件下载是否正常
- 私有下载、账号删除、AI 同意和配额限制是否按预期生效
- 前后端接口是否联通
