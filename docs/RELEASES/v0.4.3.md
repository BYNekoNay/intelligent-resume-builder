## 一、版本范围

### 1. 发送前预览（R32）

**核心不是"有个预览弹窗"，而是"预览看到的就是实际发出去的"。** 三条支撑：

1. **唯一实现**：provider 的消息组装抽成 `AiMessageAssembler`，预览与发送都调它。
   两处各拼一遍必然漂移，而漂移比没有预览更糟。`AiPromptParityTest` 断言两条路径逐字节相等。
2. **默认脱敏**：新增 `ContactRedactor`，只脱**邮箱与手机号**（替换成 `[EMAIL]`/`[PHONE]`，
   而不是删除 —— 让模型知道"这里原本有内容"）。刻意不碰 URL / 版本号 / 金额 / 正文：
   此前 `RESUME_OPTIMIZE` / `INLINE_OPTIMIZE` / `ACHIEVEMENT_GUIDANCE` / `MATERIAL_IMPORT`
   四类任务的 prompt **完全不脱敏**，用户粘进简历的邮箱电话会原样上云。
3. **令牌绑定**：`POST /api/ai/tasks/preview` 返回 messages + 脱敏摘要 + SHA-256 令牌；
   创建时服务端重算比对，缺令牌 → 40001、载荷变了 → 40901，**两者都不落库**。

预览接口只读：不写库、不调 provider（否则"取消预览"就不再是"一条都没发"）。
前端：点「AI 生成」→ 展示确切文本 → 确认才发；取消则**零请求**（e2e 断言）。

### 2. 失败保留与降级（R33）

这两条改的是**既有行为**，不是新增功能：

| 之前 | 现在 | 理由 |
| --- | --- | --- |
| 可重试失败打回 `PENDING`，worker 再跑，最多 3 次 | **一律 `FAILED`**，重试只能由用户点 | 失败任务照样占配额，自动重试会悄悄消耗额度 |
| 模型链顺延只写 `log.info` | 每次尝试记入 `AiCallResult.modelAttempts` 并落到任务结果 | 换可以换（同供应商、配额驱动），但**不能静默** |

已经满足、本版只用断言钉住的：失败不写 `result_json`、不建 `resume_version`、不落孤儿草稿、
prompt 与已选素材留在 `input_snapshot_json`。

### 3. 桌面端可安装（阶段六收尾）

- NSIS 安装包：`Zhili Setup 0.1.0.exe`（非 one-click，可改安装目录）；
- 打包产物里**只有当前版本**的 jar（此前的通配符会把 `target` 里 0.4.0/0.4.1 一起塞进去）；
- 包内无 `.env` / `secrets.env` / `resume.mv.db`，asar 内无 `ai-credentials` 字样；
- 打包后的编排用 `smoke --packaged` 验证：16s 就绪、SPA 200、桌面端点 200、退出无孤儿。

## 二、升级须知

1. **通用 AI 端点现在强制预览**：`POST /api/ai/tasks` 必须带 `input._previewToken`
   （先调 `POST /api/ai/tasks/preview` 拿）。不带 → `40001`，载荷变了 → `40901`，都不落库。
   自建客户端需要改一行。
2. **失败不再自动重试**：可重试失败也停在 `FAILED`，前端提供手动重试（`POST /api/ai/tasks/{id}/retry`）。
3. **数据库**：本版**无新增迁移**（仍是 V38）。
4. **桌面端**：换 AI 密钥仍需 DPAPI（仅 Windows），非 Windows 判不可用、不降级为明文。
