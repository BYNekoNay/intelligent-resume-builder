# 系统架构设计说明书

## 1. 设计目标

本系统架构设计遵循以下目标：

- 满足 MVP 快速落地
- 保证主流程可闭环
- 保证后续易于扩展
- 控制复杂度，避免前期过度拆分

## 2. 架构原则

- 前后端分离
- 模块化单体优先
- 领域边界清晰
- 能力逐步增强
- AI 模块可替换、可追踪、可限流

## 3. 总体架构

```text
前端 Web（Vue 3）
        ↓
后端 API（Spring Boot）
        ↓
认证模块 / 资料库模块 / 简历模块 / JD模块 / AI模块 / ATS模块 / 投递模块 / 面试模块 / 评分模块 / 导出模块
        ↓
MySQL + Redis（后续）+ MQ（后续）+ PDF渲染服务（Node.js）
```

## 4. 架构分层

### 4.1 表现层

职责：

- 接收用户请求
- 进行参数校验
- 返回统一响应结构

组成：

- Web 前端页面
- 后端 Controller

### 4.2 业务层

职责：

- 承载领域业务逻辑
- 协调模块间调用
- 管理事务和状态变化

组成：

- Service
- Domain Logic

### 4.3 数据访问层

职责：

- 访问数据库
- 管理持久化映射
- 保持查询与更新分离

组成：

- Repository / Mapper

### 4.4 基础设施层

职责：

- 鉴权
- AI 提供商接入
- PDF 导出引擎接入
- 缓存、消息队列、日志、监控

## 5. 模块设计

### 5.1 认证模块

职责：

- 用户注册
- 用户登录
- Token 签发与校验
- 当前用户上下文识别

### 5.2 简历模块

职责：

- 简历主实体管理
- 简历结构化存储
- 简历基础信息校验

### 5.3 版本模块

职责：

- 保存历史版本
- 标记当前版本
- 支持 AI 优化后生成新版本

### 5.4 职业资料库模块

职责：

- 管理用户可复用的工作经历、项目经历、技能和其他职业资料
- 维护资料状态与用户设置的引用偏好
- 为岗位定制生成提供唯一的事实来源
- 记录资料被简历版本引用的关系

### 5.5 JD 模块

职责：

- 管理目标岗位描述
- 提取关键词
- 保存解析结果

### 5.6 AI 模块

职责：

- 基于资料库 + JD 筛选相关资料并生成岗位定制简历
- 对经历缺失的成果信息提出澄清问题，并基于用户确认答案优化表达
- 基于已确认简历版本和 JD 生成求职沟通文案
- 基于 Resume + JD 生成优化结果
- 输出结构化优化建议
- 保存 AI 调用任务记录

设计要求：

- 支持多模型提供商
- 支持 Prompt 版本管理
- 支持超时和失败处理
- 输出引用资料、未引用资料及理由，且不得生成资料库以外的事实
- 所有输出声明需携带资料来源或待确认标记；服务端拒绝保存无法映射且未确认的事实
- 按任务类型执行字段白名单、同意校验、配额和幂等控制

### 5.7 ATS 模块

职责：

- 对简历版本和目标 JD 执行规则化体检
- 输出关键词、结构、完整度和可读性风险
- 为 AI 优化和成果量化引导提供可解释的输入

### 5.8 投递模块

职责：

- 关联公司、JD、简历版本、求职沟通文案和投递状态
- 保存投递反馈及后续面试结果
- 不负责自动投递或外部招聘平台同步
- 明确投递状态机、合法状态迁移和状态变更审计

### 5.9 面试模块

职责：

- 保存多轮面试问答和反馈
- 将用户确认的优质回答或改进答案沉淀为可复习资产
- 会话可选关联一次投递记录；独立训练会话不绑定投递

### 5.10 评分模块

职责：

- 计算简历与 JD 匹配分数
- 输出分项得分与缺失项
- 为前端提供解释数据

### 5.11 导出模块

职责：

- 将简历 JSON 转换为模板渲染数据
- 触发 HTML 到 PDF 的生成流程
- 管理导出状态与结果

## 6. 技术选型

### 6.1 前端

- Vue 3
- TypeScript
- Pinia
- Axios
- 不引入重型 UI 组件库；MVP 使用 Vue 组件、项目 CSS 和 `lucide-vue-next`，新增依赖须单独决策

### 6.2 后端

- Java 17
- Spring Boot 3.x
- Spring Security
- Spring AI
- Spring Data JPA
- Flyway 数据库迁移
- Hibernate Validator

### 6.3 数据与基础设施

- MySQL 8
- Redis（第四阶段，且仅在跨实例限流或缓存需求被数据证明后）
- RabbitMQ（第四阶段，且仅在数据库任务工作器无法满足负载后）
- OpenTelemetry + Prometheus + Grafana（工程增强阶段）

### 6.4 PDF 方案

- Node.js
- Puppeteer

## 7. 演进策略

### 7.1 当前形态

采用模块化单体架构：

- 便于统一调试
- 减少部署复杂度
- 更适合单人/小团队开发

### 7.2 后续拆分建议

当并发量、任务量或模块复杂度提高后，可优先拆出：

1. AI 服务
2. PDF 导出服务
3. 匹配评分服务

## 8. 核心调用流程

### 8.1 AI 优化

```text
前端 -> 创建AI任务 -> 数据库工作器抢占任务 -> 读取简历版本和JD快照 -> 构造Prompt -> 调用模型 -> 保存任务结果 -> 前端查询并逐项确认 -> 事务性创建新版本
```

### 8.2 岗位定制生成

```text
前端 -> 岗位定制生成接口 -> 读取资料库和用户筛选偏好 -> 读取JD -> 筛选资料 -> 调用模型 -> 返回草稿及选择理由 -> 用户确认后保存新版本
```

### 8.3 ATS 体检与成果量化

```text
前端 -> ATS体检接口 -> 读取简历版本和JD -> 规则校验 -> 返回风险与补充问题 -> 用户确认补充信息 -> 更新职业资料或保存新版本
```

### 8.4 投递与复盘

```text
前端 -> 投递接口 -> 关联JD、简历版本和沟通文案 -> 更新投递状态 -> AI面试记录 -> 用户确认沉淀答案资产
```

### 8.5 评分

```text
前端 -> 评分接口 -> 提取JD关键词 -> 提取简历关键信息 -> 规则计算 -> 生成说明 -> 返回评分结果
```

### 8.6 导出

```text
前端 -> 创建导出任务 -> 后台工作器读取简历版本 -> 生成受控模板数据 -> 私有调用PDF服务 -> 输出私有文件 -> 前端查询任务 -> 受控下载
```

## 9. 横切能力设计

### 9.1 统一返回结构

建议统一返回：

- code
- message
- data
- traceId

### 9.2 异常处理

需要统一处理：

- 参数异常
- 权限异常
- AI 调用异常
- PDF 导出异常
- 数据不存在异常
- AI 同意、配额、幂等和任务状态异常
- 私有文件访问和账户删除清理异常

### 9.3 日志与追踪

需要重点记录：

- 用户关键操作日志
- AI 调用耗时
- 评分执行耗时
- 导出任务状态变化
- AI 提供商、模型版本、用户同意版本、脱敏输入摘要和配额消耗

### 9.4 数据与任务边界

- AI 任务统一采用异步契约：创建接口只返回 `taskId` 和初始状态，结果由任务查询接口返回
- `resume_version` 保存生成上下文快照，包括 JD、资料来源、模型和提示词版本；资料和 JD 的后续编辑不得改写历史上下文
- 导出文件通过受控下载或短时签名地址访问，数据库不暴露可长期公开访问的文件 URL

### 9.5 MVP 数据库任务工作器

- 使用数据库轮询，不依赖 Redis 或 MQ。
- 工作器原子抢占 `PENDING` 或租约过期任务；抢占、续租、成功和失败更新都必须校验租约所有者。
- 应用重启后，租约过期的 `RUNNING` 任务回到可重试状态；不可重试错误直接进入 `FAILED`。
- AI 调用和确认写版本是两个事务边界；AI 成功不等于用户已经采纳。
- 幂等键相同且请求摘要一致时返回原任务；摘要不一致时返回冲突。

### 9.6 AI 不可信输入边界

- JD、简历、职业资料和用户粘贴文本全部视为不可信数据，只能放入明确分隔的数据区，不能被当作系统指令。
- MVP 的 AI 任务禁止工具调用、网页访问、文件访问和任意 URL 请求。
- 模型输出必须通过 JSON Schema、字段白名单、长度限制和来源映射校验；校验失败不得进入待确认结果。
- 对“忽略系统规则”“读取其他用户数据”“访问 URL”等 Prompt Injection 输入建立必测用例。

### 9.7 PDF 服务信任边界

- PDF 服务只监听私有网络接口，仅接受后端携带轮换服务令牌的请求，不直接暴露给浏览器。
- 后端只发送结构化简历 JSON 和固定模板代码；PDF 服务不得接收任意 HTML。
- 模板必须转义所有用户字段，禁止 `file:`、`http:`、`https:` 等外部资源和 Chromium 网络请求。
- 每个任务设置渲染超时、最大页面数、最大输入和输出大小、CPU/内存并发上限；临时文件在成功或失败后清理。
- 存储键使用随机不可猜值，不包含用户名、用户 ID 或简历标题；下载授权由后端负责。

### 9.8 传输、存储与秘密

- 正式环境所有外部流量强制 HTTPS；内部 PDF 调用位于私有网络并使用服务认证。
- MySQL 数据卷、备份和 PDF 存储必须加密；数据库账号按服务最小权限分离。
- JWT、AI 和 PDF 服务密钥只能来自秘密管理或受控环境变量，必须支持轮换且不得写入日志。

## 10. 结论

本系统架构采用“简单但可演进”的策略，优先保障产品核心链路落地，同时为后续性能优化、异步任务和服务拆分保留空间。
